## Kontrak implementasi invoice / receipt-allocation / rekonsiliasi-aging (3 Oktober 2026)

- Invoice hanya dari completed/accepted delivery atau proof jasa dengan activation policy; satu customer/proyek/plant/periode/currency/treatment kompatibel. Harga source immutable; charge freight customer tidak mengambil biaya internal. Draft/issue tidak memposting stok atau realisasi PO lagi.
- Source quantity/freight tidak boleh ditagih dua kali, termasuk backdated issue sebelum cancellation sumber tagihan lama. Shared transaction lock memeriksa dated claims serta saldo invoice/receipt sepanjang timeline, bukan saldo saat ini saja.
- Finance menerbitkan invoice normal tanpa tambahan approval Manager. Tax/term/due date disnapshot dari version verified; ACCOUNT/TAX/TERM maker Finance, attest Finance kedua, verifikasi Manager berbeda akun. Draft boleh menyimpan parameter belum tersedia; issue butuh tax dan kredit/kontrak butuh term, receipt post butuh account yang mengizinkan currency tersebut.
- Receipt actual terpisah allocation dan PPh. Allocation posted ≤ receipt tersedia dan ≤ outstanding, customer/currency/plant sama. PPh menggunakan nilai certificate aktual, Finance kedua verify, bukan cash receipt atau tarif asumsi. Certificate tidak dikreditkan dua kali; split certificate belum aktif.
- Outstanding = signed invoice efektif − signed allocation − signed PPh verified; payment status derived. Header receipt hanya membentuk dana tersedia, tidak mengurangi invoice lagi. Nilai uang exact Decimal, tidak Number.
- Correction/cancellation Finance request→Manager approve, maker/submitter/pengesah sumber berbeda approver, dependent allocation/PPh diselesaikan dahulu. Original dan correction period harus terbuka; inverse event mempertahankan history. Tidak ada delete, refund/write-off/credit note otomatis.
- Rekonsiliasi dan aging membaca snapshot transaksi konsisten dan signed effective events as-of akhir hari WIB. Invoice/receipt yang direversal kemudian tetap muncul pada posisi sebelum reversal. Missing due date exception, belum jatuh tempo, due hari ini dan overdue 0–30/31–60/61–90/>90 dibedakan. Sumber unbilled saat ini diberi label tersendiri.
- Pending finance/events termasuk fingerprint close inventory. Ini dependency minimum dan tidak menyatakan generic closing/export/migration AR legacy sudah lengkap.

## Kontrak implementasi quotation / Customer PO / delivery (3 Oktober 2026)

- Quotation opsional; SO adalah sumber order. Kredit/kontrak memakai PO approved customer/proyek/plant yang cocok; tunai boleh tanpa PO. Source harga/currency/tax/minimum/freight disnapshot, deviasi meminta Manager dan tidak melewati minimum. Harga umum tidak menjadi jalan melewati kontrak customer.
- Initial PO dan amendment membutuhkan peer PC verification lalu Manager. Root/key/item/UOM tetap antarversion; realized tidak berkurang oleh rejected/return tanpa policy. Duplicate nomor PO customer/proyek tidak membuat commitment resmi kedua.
- Delivery source mempunyai DO stable dan stock/PO/SO capacity diperiksa ulang dalam transaksi shared inventory. Dispatch sekali; completion/pickup retry tidak membuat ledger atau fulfillment kedua. Jasa/sewa tidak mempunyai material stock-out.
- Event fisik rekomendasi menjadi EVENT_POLICY UNVERIFIED terlebih dahulu. Sign-off PC/operasional dan Finance berbeda akun, lalu Manager berbeda maker/signatories dengan bukti; baru dapat mengaktifkan dispatch dan, bila eksplisit, pickup gabungan. Fixture bukan pengesahan perusahaan.
- Accepted + rejected = quantity dispatch/layanan; eligibility invoice accepted-only completed/proof. Return/billing/allocation membutuhkan domain berikut, bukan stock-in/reversal otomatis. Pending/in-transit delivery masuk inventory closing fingerprint. Version/source/realization/keputusan mempertahankan audit dan scope.

## Kontrak implementasi produksi / blending / BBM (3 Oktober 2026)

- Writer produksi dan BBM memakai `appendStockMoves` di transaksi lock/Serializable yang sama dengan inventory; public inventory input tidak boleh membuat source kind operasional secara manual.
- Maker menyimpan/edit draft, submit; Admin PC berbeda maker/submitter memverifikasi actual; posting hanya source VERIFIED. Config/version disahkan Manager berbeda maker. Posted source dan quantity snapshot tidak diedit.
- Consumption actual bukan CSR kedua; klasifikasi output mencegah hasil blending menjadi output SC. BBM proses AMP menautkan usage posted dengan dependency tanpa ledger fuel kedua.
- Numerator BBM per plant/periode berasal dari usage posted unik dengan purpose produksi dan flag inclusion snapshot; denominator hanya output SC/BP/AMP posted efektif. Reversal menonaktifkan source; output nol N/A. Konversi berbeda dimensi/kemasan memerlukan version verified.

## 4. Lifecycle, transaksi, dan posting

16. Status posting umum Draft → Submitted → Posted → Reversed; approval dan status perjalanan terpisah. Invoice Draft → Issued → Partially Paid → Paid; Cancelled melalui kontrol. Mapping APPROVED/COMPLETED existing harus berdasarkan bukti posting, bukan mengganti enum sembarangan.
17. Posted/issued tidak diedit/dihapus langsung. Koreksi memakai reversal/adjustment/cancel beralasan, approval, period guard dan dependency check. Master nonaktif menyimpan histori; nomor issued/cancelled tidak dipakai ulang.
18. Semua mutasi saldo dari ledger immutable dengan source type/ID/line/event, item, lokasi, quantity/UOM stok, effective date, actor, key dan reversal link. Saldo adalah projection; tidak ada field edit saldo. Uang/quantity menggunakan arithmetic Decimal exact; format Indonesia hanya presentasi.
19. Satu posting service per domain, transaksi DB atomic dan validasi ulang setelah lock/serializable. Stok negatif dan overdelivery diblokir termasuk request bersamaan/reversal. Unique key berasal dari source-event/client key stabil; retry memberi hasil sama. UUID baru tiap transfer tidak cukup. Tangani serialization conflict dengan retry terbatas atau conflict yang jelas.
20. Transfer membuat sumber/tujuan konsisten; konversi UOM harus sah. Opname memakai snapshot cut-off, fisik/bukti/metode, selisih terhadap buku cut-off; movement sesudahnya tidak tertimpa. Adjustment/CSR mandiri menunggu Manager berbeda akun. Produksi actual consumption tidak diposting lagi sebagai CSR.
21. Produksi SC/BP/AMP berbeda kebutuhan/UOM; actual input-output yang verified diposting bersama. Mix version pembanding, bukan pengganti actual. Blending transaksi terpisah; output tidak digandakan dari SC. Ton dan m³ tidak dijumlahkan; konversi berbeda dimensi membutuhkan density version verified.
22. Customer PO wajib kontrak/kredit; tunai SO tanpa PO sah. Semua stock-out penjualan mempunyai delivery/DO termasuk pickup. Overdelivery membutuhkan amendment PO disetujui, tanpa bypass. Posting delivery mengurangi stok/realisasi PO tepat sekali; completion dan invoice tidak mengurangi stok lagi. Event dispatch resmi menunggu OPEN-04 sebelum aktivasi.
23. Service/rental bukan inventory item; invoice jasa tidak otomatis membuat material-out. Pisahkan harga barang, freight customer dan biaya internal. Snapshot harga/UOM/konversi/tax/term; harga khusus meminta Manager. Harga asli 1 Juli 2026, LOCO Samalore, belum PPN dan minimum hotmix 200 ton per order/kontrak final tidak berarti angka harga boleh dikarang.
24. BBM memakai satu sumber ledger: receipt/usage/transfer; usage referensi alat/vehicle/plant/purpose. SC/BP liter per m³; AMP liter per ton; zero output N/A+exception; nonproduksi terpisah. AMP referensi usage yang sama tanpa stock-out kedua. Jerigen/HM-KM/KPI ABT mengikuti parameter verified/gate.
25. Invoice dari completed/accepted delivery eligible atau bukti service, source quantity tidak double-billed. Validasi customer/proyek/periode/ketentuan kompatibel. Issue kredit memerlukan term/due date sah; tax rule version Finance sah, bukan default demo.
26. Receipt uang aktual terpisah allocation dan PPh verified. Allocation ≤ receipt dan ≤ outstanding, customer sama; overpayment unallocated. Outstanding = invoice efektif − allocation posted aktif − PPh verified efektif; header receipt tidak dikurangkan lagi. Status sistem; aging due-date/as-of, buckets 0–30/31–60/61–90/>90, belum jatuh tempo terpisah.
27. Periode closed menolak posting/backdate/reversal sampai reopen approved diaudit. Closing checklist PC mencakup rekonsiliasi Finance; Manager bukan maker. Reversal menolak sumber berturunan sampai invoice/payment/stock terkait diselesaikan sesuai policy, tidak menghapus turunan otomatis.
28. Audit mencakup posting/approval/reversal/master/export/config beserta actor, alasan dan before-after relevan. Config perhitungan versioned dan Manager-approved; numbering atomic unique dengan scope/pattern sah. Depresiasi garis lurus memakai parameter verified dan unik aset-periode, Finance verification.
